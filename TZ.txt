2. CMD СЛОЙ (ТОЧКА ВХОДА)

cmd/todo/main.go

Назначение:
- только запуск приложения

Что внутри должно быть:
- создание storage
- создание service
- создание history
- создание app
- запуск app

КРИТИЧЕСКОЕ ПРАВИЛО:
- НИКАКОЙ логики
- НИКАКИХ бизнес-операций

3. APP СЛОЙ (СБОРКА ВСЕГО)

internal/app/app.go

Назначение:
- связывает UI, Service, Storage, History

Что внутри:
- структура App
- зависимости: service, ui, history

Методы:
- Run() — главный цикл приложения

Здесь происходит:
показ меню → получение команды → вызов service → вывод результата

4. TASK СЛОЙ

internal/task/model.go

Назначение:
- описание структуры Task

Что внутри:
- структура Task: ID, Title, Description, Done, CreatedAt, UpdatedAt

Объясняешь:
- это просто данные
- здесь нет логики

internal/task/service.go

Назначение:
- бизнес логика задач

Что внутри:
структура Service:
- хранит: storage, history

Методы:
- AddTask
- GetTasks
- UpdateTask
- CompleteTask
- DeleteTask

ВАЖНО:
- не работает с консолью
- не читает input
- не пишет print

5. STORAGE СЛОЙ

internal/storage/storage.go

Назначение:
- интерфейс хранилища

Что внутри:
интерфейс: Load() ([]Task, error), Save([]Task) error

Объясняешь:
- это абстракция
- можно заменить файл на БД

internal/storage/file_storage.go

Назначение:
- реализация хранения в файле

Что внутри:
- структура FileStorage: путь к файлу

Методы:
- Load
- Save

Что важно объяснить:
- если файла нет → создать
- если пустой → вернуть пустой список

6. HISTORY СЛОЙ

internal/history/history.go

Назначение:
- интерфейс истории

Что внутри:
методы: AddRecord(action string), GetHistory() []string

internal/history/file_history.go

Назначение:
- запись истории в файл

Что внутри:
- структура: путь к файлу

Методы:
- AddRecord
- GetHistory

Что сохраняется:
[2026-01-01 12:00] ADD Task 1

7. UI СЛОЙ

internal/ui/menu.go

Назначение:
- отображение меню

Что внутри:
- функции: ShowMenu(), ShowTasks(), ShowMessage()

internal/ui/input.go

Назначение:
- получение ввода пользователя

Что внутри:
- функции: ReadCommand(), ReadTaskData(), ReadID()

Объясняешь:
- UI отвечает только за ввод/вывод

8. DATA СЛОЙ

data/tasks.json
Назначение: хранение задач

data/history.log
Назначение: хранение истории

9. ПОТОК ВЫПОЛНЕНИЯ

Объясни студентам прямо как схема:

main.go
   ↓
app.Run()
   ↓
UI (меню)
   ↓
Service (логика)
   ↓
Storage (файл)
   ↓
History (лог)

10. ЧТО ТЫ ОБЯЗАН ПРОГОВОРИТЬ

1. Почему такая структура
- разделение ответственности
- масштабируемость

2. Почему интерфейсы
- можно заменить файл на БД

3. Почему нельзя всё в main.go
- нечитаемо
- не расширяется

11. КАК СТРОИТЬ ПРОЕКТ ПО ЭТАПАМ

ЭТАП 1: структура папок, main.go
ЭТАП 2: model.go
ЭТАП 3: storage
ЭТАП 4: service
ЭТАП 5: UI
ЭТАП 6: history
ЭТАП 7: рефакторинг

ТИПИЧНЫЕ ОШИБКИ (ОЧЕНЬ ВАЖНО)

1. Архитектура
- всё в одном файле
- нет папок

2. Слои
- UI вызывает storage напрямую
- service печатает в консоль

3. Storage
- перезаписывают файл неправильно
- не обрабатывают ошибки

4. Service
- нет поиска по ID
- дублирование кода

5. UI
- нет валидации ввода
